## 1. 期刊质量筛选更灵活

v1.6 增加了 `exempt_journals` 配置，允许指定期刊直接放行，不再进入 EasyScholar 质量门控。

- 配置位置：`config/workflow_rules.json` 的 `triage.journal_quality_filter.exempt_journals`
- 代码位置：`tools/lib/easyscholar_journal_quality_gate.mjs`
- 生效逻辑：在 `shouldQueryJournalQuality()` 中做 NFKC 归一化后匹配，命中即跳过期刊质量查询
- 实际用途：针对缺失 IF/分区、但用户明确要收录的新期刊，减少误筛和无效 API 调用

示例：

```json
"exempt_journals": ["Brain and Environment"]
```

## 2. MCP 调用稳定性显著提升

针对 Zotero MCP 在批量写回、翻译回填、元数据重试中出现的 `-32700 Parse error`，v1.6 做了两阶段修复：

### 第一阶段：重试与退避增强

- 在 `createItem` 等关键调用处增加重试与 `1s * attempt` 退避
- 扩展瞬态错误匹配规则，覆盖 `-32700|Parse error|timeout|database busy|lock conflict`
- 相关提交：`95b2972`

### 第二阶段：全局请求串行化

- 在 MCP 调用层加入全局 `Promise` 互斥链，避免并发请求打到 SQLite 造成锁冲突
- 关键参数调整：
  - writeback 并发：`10 -> 1`
  - writeback 重试：`1 -> 4`
  - mcpToolCall 重试：`3 -> 5`
  - backoff：`500ms -> 1000ms`
  - translation 并发：`10 -> 1`
  - metadataRetry：`2 -> 4`
- 主要受影响文件：
  - `tools/mcp_bulk_writeback.mjs`
  - `tools/mcp_translation_backfill.mjs`
  - `tools/translation_backfill_support.mjs`
- 相关提交：`ff34ada`

最终效果：MCP 批量操作更稳定，尤其在长任务和重试场景下不再容易出现解析错误。

## 3. 自动化链路健壮性修复

在公开发布目录 `public_release/Automation/tools/` 中，v1.6 修了 3 个影响自动化可靠性的点：

### 3.1 MCP readiness 检查更真实

- 文件：`tools/check_zotero_mcp_ready.mjs`
- 原问题：MCP 状态检查在异常情况下仍可能返回 `ok`
- 修复：加 `try-catch`，探测异常时返回 `ok: false`

### 3.2 PubMed 配置复用更合理

- 文件：`tools/run_research_os_pipeline.mjs`
- 修复：`fetchPubMed()` 支持接收可选 config，避免冗余配置加载

### 3.3 Stage1 缺失时不再继续执行

- 文件：`tools/run_zotero_literature_filter.mjs`
- 原问题：Stage1 跳过或失败后，流程仍可能继续往下跑
- 修复：Stage1 结束后检查关键 artifact，缺失则中止后续阶段

## 4. 用户反馈迁移不会被 Stage2 覆盖

v1.6 中确认并明确了一个重要行为边界：

- `feedback_item_actions` 在 Stage1 开头处理上一轮反馈，移动已有条目的集合归属
- Stage2 使用三层去重索引，对已存在条目直接命中去重并跳过
- 因此 `feedback_item_actions` 的迁移结果不会被 Stage2 覆盖

这一点在当前实现中属于**已确认的稳定行为**，不是新 bug。
